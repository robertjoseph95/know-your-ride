# Deep-link v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the browser Back/Forward buttons step through the spec modal — opening a vehicle pushes a history entry, Back closes it, Forward reopens it — without breaking v1's shareable URLs.

**Architecture:** Build on v1 (`kyrSyncURL`/`kyrApplyURL`, `__kyrCurV`/`__kyrBooting`). Add two flags: `__kyrReplaying` (suppresses history writes while applying URL state) and `__kyrPushedModal` (do we own a poppable entry). The modal-open URL write splits into `pushState` (user open) vs `replaceState` (replay/load). User-close does `history.back()` when we own the entry, else `replaceState(base)`. One `popstate` listener re-applies state, wrapped in `__kyrReplaying`. Tabs/code stay `replaceState` (unchanged).

**Tech Stack:** Vanilla JS in a single file (`wrench_demo.html`), built to `wrench_deploy/index.html` via `files/04_rebuild_demo.py` + `_deploy_sync_specs.py`. No test runner — verification is `node --check` (syntax) + `preview_eval` assertions (runtime) via the Claude_Preview MCP.

### Task 3: Rework close into UI-close + history-aware close

**Files:**
- Modify: `wrench_demo.html` (`closeModal`)

- [ ] **Step 1: Replace `closeModal`.** Find the current one-liner:

```js
function closeModal(){document.getElementById('overlay').classList.remove('open');document.body.style.overflow='';__kyrCurV=null;kyrSyncURL();}
```

Replace with:

```js
function closeModalUI(){document.getElementById('overlay').classList.remove('open');document.body.style.overflow='';__kyrCurV=null;}
function closeModal(){
  if(__kyrReplaying){closeModalUI();return;}
  if(__kyrPushedModal){__kyrPushedModal=false;history.back();return;}
  closeModalUI();kyrSyncURL();
}
```

Rationale: during replay (popstate) we only touch the UI. If we own a pushed entry, `history.back()` consumes it and the popstate handler (Task 4) performs the UI close. Otherwise (deep-link / auto-reopen entry) we close the UI and `kyrSyncURL()` rewrites the URL to base + Garage — staying in the app.

### Task 4: Add the popstate listener

**Files:**
- Modify: `wrench_demo.html` (`DOMContentLoaded` — register alongside the existing keydown handler)

- [ ] **Step 1: Register the listener.** Find the boot block edited in Task 1 (the `__kyrBooting=false; __kyrReplaying=true; try{...}finally{...}` block). Immediately AFTER that block, add:

```js
  window.addEventListener('popstate',function(){
    __kyrReplaying=true;
    try{
      var p=new URLSearchParams(location.search);
      var v=p.get('v');
      var ov=document.getElementById('overlay');var open=ov&&ov.classList.contains('open');
      if(v&&VEH[v]){if(!open)openModal(v);}
      else{if(open)closeModalUI();var tab=p.get('tab')||'garage';if(typeof switchTab==='function')switchTab(tab);}
    }catch(e){}
    __kyrReplaying=false;
  });
```

Note: the close branch calls `closeModalUI()` (not `closeModal()`) directly — we're already replaying, and we must not re-enter the history logic. `switchTab` is guarded so a tab in the URL is restored on Back to a tab state; with modal-only scope this normally just lands on Garage.
