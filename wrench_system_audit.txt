─── 2.2 AUTHENTICATION (api/auth.py) ───────────────────────────────────────
CORRECT: scrypt KDF (n=2^14,r=8,p=1,dklen=32) with per-user 16-byte CSPRNG salt
(auth.py:59-64); constant-time hmac.compare_digest (auth.py:70); session tokens
= secrets.token_urlsafe(32) (auth.py:203); tokens validated server-side on every
protected request (garage.py:130-132, garage-logs.py:89-91); 30-day session TTL;
email regex + 8-char min password on signup.

> ISSUE 2.2-A
- SEVERITY: MEDIUM
- DESCRIPTION: No brute-force / rate-limiting on login. _login (auth.py:156-176)
  has no per-email/per-IP attempt counter or lockout — unlimited password
  guessing / credential stuffing (scrypt cost only slows it).
- AFFECTED: wrench_deploy/api/auth.py:156-176
- RECOMMENDED FIX: Add Redis counters login_fail:{email} / login_fail_ip:{ip}
  with TTL; 429 after N failures. (Or Vercel WAF rate limit on /api/auth.)

─── 2.3 API ENDPOINTS ──────────────────────────────────────────────────────
CORRECT: No SQL injection — serverless functions use Redis/HTTP, not SQL; the
local wrench_serve.py uses fully parameterized (?) SQLite queries. Stripe
webhook signature IS verified (webhook.py:49-54, stripe.Webhook.construct_event,
400 on failure) before processing.

> ISSUE 2.3-A
- SEVERITY: LOW
- DESCRIPTION: verify-subscription.py (GET ?email=) returns subscription/

- AFFECTED: wrench_deploy/api/verify-subscription.py:52-77
- RECOMMENDED FIX: Require the session bearer token; derive email from session.

> ISSUE 2.3-B
- SEVERITY: LOW

- AFFECTED: all api/*.py _send()/_json() (e.g. guide.py:166, identify-part.py:143)
- RECOMMENDED FIX: Restrict CORS to https://knowyourride.net for AI/garage.

owner's-manual wording, plaintext PII. COMPLIANT: affiliate tag/disclosure,
AI-guide & fitment disclaimers, scrypt hashing, thorough Terms/Privacy docs.


╔══════════════════════════════════════════════════════════════════════════╗
SECTION 4: PERFORMANCE & RELIABILITY
╚═══════════════════════════════════════════════════════════════════════════╝

─── 4.1 PAGE SIZE ──────────────────────────────────────────────────────────
Measured: index.html = 31,137,348 bytes (29.69 MiB). The inline const __D__=
JSON blob = 31,025,672 bytes = 29.59 MB = 99.65% of the file. Everything else
(HTML+CSS+all JS) ≈ 110 KB (0.35%). Dataset is 100% inline, parsed synchronously
on load, NOT lazy-loaded. External resources: Google Fonts (3 families/11
weights), GA gtag (G-7RE1GC9S5Q). No Stripe.js/CDN libs (client is dependency-
light — good).

> ISSUE 4.1-A
- SEVERITY: HIGH
- DESCRIPTION: The entire 29.59 MB dataset is embedded inline and parsed on the
  main thread every cold load. Even with gzip/brotli on the wire, the browser
  downloads/decompresses/parses ~29.6 MB before interactive — punishing on
  mobile, and re-fetched whenever the hash changes (served max-age=0,
  must-revalidate, so revalidated every navigation).
- AFFECTED: wrench_deploy/index.html (__D__ blob); files/04_rebuild_demo.py
- RECOMMENDED FIX: Split the dataset out of the HTML. (a) ship a small index +
  lazy-fetch per-vehicle JSON from the existing vehicles/ & dtc/ dirs; or (b)
  at minimum move __D__ to a separate hashed .json with Cache-Control:
  immutable so it caches across visits. Either cuts initial HTML ~30 MB -> ~110 KB.

> ISSUE 4.1-B
- SEVERITY: LOW
- DESCRIPTION: Google Fonts loads 3 families / 11 weights (render-blocking).
- AFFECTED: index.html font <link>
- RECOMMENDED FIX: Trim to weights actually used / self-host (display=swap
  already set).

─── 4.2 CACHING ────────────────────────────────────────────────────────────
DONE WELL: youtube.py cached in Redis 30 days; guide.py cached in Redis 90 days
(+ safety-service short-circuit). identify-part.py intentionally uncached (every
image unique) but budget-gated.

> ISSUE 4.2-A
- SEVERITY: MEDIUM
- DESCRIPTION: vin/[vin].py makes a live NHTSA vPIC call on EVERY request with
  NO caching (doesn't import Redis), despite VIN decodes being perfectly
  deterministic — repeated work + per-request dependency on NHTSA uptime.
- AFFECTED: wrench_deploy/api/vin/[vin].py
- RECOMMENDED FIX: Cache decoded VIN in Redis keyed by VIN, long/no TTL (reuse
  the _redis() helper from youtube.py).

> ISSUE 4.2-B
- SEVERITY: LOW
- DESCRIPTION: recalls.py makes a live NHTSA recalls call per request, uncached.
- AFFECTED: wrench_deploy/api/recalls.py
- RECOMMENDED FIX: Add a ~24h Redis cache keyed by make|model|year.

─── 4.3 ERROR HANDLING ─────────────────────────────────────────────────────
DONE WELL: every handler uses a private _send/_json with explicit status codes;
Redis-down is handled gracefully everywhere (503, no crash; identify-part fails
closed); Anthropic-down returns a graceful 200 {error:...} (no 500); Stripe
webhook always returns 200 after signature check.

> ISSUE 4.3-A
- SEVERITY: MEDIUM
- DESCRIPTION: 7 endpoints echo the raw exception text to the client
  (info leak — library/vendor internals): youtube.py:62, guide.py:154,
  identify-part.py:102, vin/[vin].py:82, recalls.py:29, subscribe.py:38,
  webhook.py:54 (all f"...: {e}"). These are caught exceptions (not full
  tracebacks — Vercel wouldn't surface a Python traceback), but the messages
  leak internals.
- AFFECTED: the 7 endpoints above
- RECOMMENDED FIX: Log {e} server-side; return a generic client message.

> ISSUE 4.3-B
- SEVERITY: LOW
- DESCRIPTION: No custom 404 page (no wrench_deploy/404.html; no notFound in
  vercel.json) — unknown routes fall back to Vercel's default 404.
- AFFECTED: wrench_deploy/ (missing 404.html)
- RECOMMENDED FIX: Add a branded 404.html (Vercel serves root 404.html
  automatically for static deploys).

─── 4.4 VERCEL FUNCTION LIMITS ─────────────────────────────────────────────
Function count: 13 Python functions (auth, garage, garage-logs, guide,
identify-part, obd, promo, recalls, subscribe, verify-subscription, vin/[vin],
webhook, youtube). Well under the Pro limit. NOTE: this is exactly the count
that broke Hobby-plan deploys earlier; now on Pro it's fine.

> ISSUE 4.4-A
- SEVERITY: MEDIUM
- DESCRIPTION: No maxDuration or memory config anywhere (vercel.json only sets
  includeFiles for guide.py). External timeouts (requests/urllib timeout=15,
  and youtube.py makes TWO sequential 15s calls = 30s worst case) can EXCEED
  the platform function limit, so a slow upstream gets hard-killed mid-call
  rather than returning a clean error. verify-subscription.py can make up to
  ~40 Stripe calls in a loop.
- AFFECTED: vercel.json; youtube.py, guide.py, identify-part.py,
  verify-subscription.py
- RECOMMENDED FIX: Set explicit per-function maxDuration (e.g. 30s for AI/
  youtube/verify-subscription) and lower per-request external timeouts BELOW
  maxDuration (e.g. 8s) so code returns a clean JSON error first. Optionally set
  memory for AI functions.

SECTION 4 ROLL-UP: HIGH(1): 29.6 MB inline blob. MEDIUM(3): VIN no cache, raw
exception leak, no maxDuration/timeout mismatch. LOW(2): no 404 page, font
weights. DONE WELL: 30d/90d caches, fail-closed budget guard, graceful Redis/
Anthropic-down handling, no client-side third-party JS.
